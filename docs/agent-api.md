# Agent diagnostics API

Read-only REST API consumed by the ThemeIsle support agent. It exists so the
agent can inspect a site's environment, product state and logs without using
the temporary admin account.

## Authentication

Every route requires the **Agent Token** (`ppa_...`) shown on the Support
Parrot page right after the parrot is generated. Send it as a header — never
in the URL:

```
Authorization: Bearer ppa_xxxxxxxx...
```

`X-Parrot-Token: ppa_xxxxxxxx...` is accepted as a fallback for servers that
strip the `Authorization` header.

The token is stored hashed (SHA-256), shares the parrot's 5-day expiry, and is
revoked by "Release parrot" or regenerated by "Regenerate token". Requests are
rate limited (30/hour).

## Routes

Base: `https://example.com/wp-json/pirate-parrot/v1` (on sites without pretty
permalinks, `rest_url()` yields the `?rest_route=` form — the "Agent endpoint"
row on the parrot page always shows the correct base).

| Route | Purpose |
|---|---|
| `GET /manifest` | Discovery: `schema_version`, expiry, scopes, available sections. Fetch this first. |
| `GET /site` | Curated environment info: WP/PHP/DB versions, locale, active theme + plugins, debug flags, memory limits. |
| `GET /products` | Index of registered product diagnostics providers. |
| `GET /products/{slug}` | One provider's payload. The provider callback only runs when this route is hit. |
| `GET /logs?plugin=&per_page=&page=` | Parrot log buffer, newest first, paginated (default 50, max 100 per page). |

Responses are JSON, `Cache-Control: no-store`, capped at 256 KB per section,
and pass through a key-name redaction backstop (`key`, `secret`, `password`,
`credential`, `token`, `auth`) before leaving the site.

## Registering a product provider

Products expose their own diagnostics through the
`pirate_parrot_register_diagnostics` filter:

```php
add_filter( 'pirate_parrot_register_diagnostics', function ( $providers ) {
    $providers['my-product'] = array(
        'label'    => 'My Product',
        'callback' => 'my_product_agent_diagnostics', // runs lazily, only on /products/my-product
    );
    return $providers;
} );
```

Provider rules:

- Return a plain array of scalars/arrays; it is JSON-encoded as-is.
- **Never include secrets.** Report license *status*, not the license key.
  The redaction backstop exists for mistakes, not as a feature.
- Stay under the 256 KB cap; summarize instead of dumping.
- Callbacks must be cheap enough to run on demand — they are invoked on every
  request to your section (no caching is done for you).
- A provider that throws or returns `WP_Error` fails only its own section
  (HTTP 500); the rest of the API is unaffected.

## Compatibility

The API code is parse-compatible with legacy PHP and degrades safely: on
WordPress < 4.7 (no REST API) the routes are simply not registered and the
rest of the plugin keeps working.
